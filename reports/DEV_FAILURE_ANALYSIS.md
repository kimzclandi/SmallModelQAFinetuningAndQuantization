# 开发集失败分析：先诊断拒答

只分析 74 条开发集，不用测试题生成训练样本。开发集包含 33 条有答案、41 条无答案。

自动症状统计：19 条完全正确且格式合规；14 条错误/部分片段；38 条无答案却输出了原文片段；3 条格式或非原文输出。每条失败的根因字段均为 `unverified`，不是自动确认的“知识缺失”。

| 开发样本 ID | 观察 | 可以支持的结论 | 尚不能支持的结论 |
|---|---|---|---|
| 5ad56aea5b96ef001a10ae49 | 无答案题，输出 `No_answer` | 严格拒答格式失败；存在拒答意图的可能 | “完全不懂拒答” |
| 5ad5364c5b96ef001a10ab90 | 无答案题，输出原文 `problem instance` | 原文抽取不保证问题被文段支持 | 已确定是知识缺失 |
| 56e17a7ccd28a01900c679a2 | gold 为 problem，预测 computational problem，F1=2/3 | 有部分重叠，边界选择影响 EM | 模型完全不会回答 |
| 56e17a7ccd28a01900c679a4 | gold 为 instance，预测 solution | 抽错了原文概念 | 已证明训练数据不足 |

输入是文段/问题；输出是症状队列和待验证假设。机制是将严格格式、答案重叠和可回答性分开看。限制是 reference 可能不覆盖所有合理别名，自动标签不直接说明内部原因。

下一轮优先研究“不可回答时正确拒答”。先人工读开发集文段，检查否定词、概念替换与标注，再用开发集对比严格格式与预先登记的诊断性别名解析；原始主指标保持不变。若诊断支持训练改进，只从 train 来源补充/筛选 NO_ANSWER 示例，再与等预算 gold-SFT/教师响应训练比较。

采用标准需在实验前冻结：同时改善拒答和整体质量、检查有答案题是否因过度拒答退化。测试集只在候选冻结后做预定评估，不能为了提升此报告结果修改测试标签。本轮没有修复训练，也没有“数据飞轮已完成”的结论。
