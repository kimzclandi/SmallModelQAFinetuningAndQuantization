# 已有 ChatGPT Pro：手工教师候选数据流程

用户已确认有 ChatGPT Pro，目标岗位方向为华为 AI 模型工程师；具体 JD 尚未提供。当前选择先准备小规模候选回答，不开通额外 API、不购买算力。本项目尚未登录、操作或向 ChatGPT 上传任何数据。

## 现在要做的操作

1. 在 ChatGPT 新建一个普通对话，选择你账号可用的模型；记下界面显示的**模型名称/模式**。Pro 是订阅等级，不是实验中足够准确的模型标识。
2. 上传 `data/teacher-pilot-v1/CHATGPT_REQUEST.md`，发送：“请执行文件中的任务，返回完整 JSON；不要联网搜索，保留全部 24 个 ID，不要省略条目。” 也可以直接复制文件全文。
3. 保存原始回答或生成的 JSON 文件。不要手改错误答案、补全漏题或只保留好结果；出现缺失/格式错误时也保留原始版本，后续重试另存新版本。
4. 将回答文件发回当前项目对话，并说明模型名称/模式与实际生成日期。若模型不显示底层 snapshot、temperature 等，记录为未提供，不推测。

此文件约几十 KB，只包含许可明确的训练数据片段。不要上传整个仓库、gold 文件或任何 dev/test 文件。数据来源、归属和 CC BY-SA 4.0 说明见 DATA_LICENSE.md。

## 实验机制与边界

输入：24 条训练集的 id/context/question。输出：同 ID 的答案原文片段或严格 NO_ANSWER。教师仅给回答文本，后续若获准使用并完成训练，只能称响应/序列蒸馏，不能称 logits 蒸馏。

选择按固定 hash 排序，在原训练集中分层取 12 条有答案和 12 条不可回答；这是用 gold 可回答性进行的抽样，但 gold 不进入教师请求。平衡小样本用于检查生成与导入流程，不代表完整训练分布，不能凭 24 条效果宣称正式收益。

导入检查包括 schema、ID 精确覆盖、训练来源 hash、请求内容一致性、原文连续片段或 NO_ANSWER。它**不验证语义正确性**，不自动按 gold 丢弃错误回答，也不会开始训练。原始响应按字节保存；候选数据记录 `imported_candidates_not_approved_for_training`，在检查质量与适用训练/再分发条款后才能转为训练数据。

如果 ChatGPT 的底层版本、系统配置、采样参数不可固定，只能冻结已采集的响应重现后续训练，不能保证重新请求得到相同回答。后续正式对照应使用相同训练 IDs、学生初始化和训练预算，比较 gold-SFT 与教师响应训练；先在 dev 决策，不用 test 选方案。

## 本地工具

- 重新生成请求包：`.venv/bin/python -m qa_lab.teacher_io pack --output work/teacher-pilot-rebuild`
- 查看导入参数：`.venv/bin/python -m qa_lab.teacher_io import --help`
- 导入需要 request pack、原始 JSON、界面模型名、实际日期与新的输出目录；拒绝覆盖旧记录。
- 单元测试中的合成响应只存在 pytest 临时目录，标记 SYNTHETIC UNIT TEST ONLY，不作为教师运行记录。
