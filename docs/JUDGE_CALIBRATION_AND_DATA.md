## 数据和实验顺序

1. 64 条合成校准样本，每类正负各半，比较三种核验提示；所有候选都在文段出现，负例要求判断语义关系。
2. 贪心标签输出的三种提示均未同时达到 TPR/TNR ≥87.5%。另行冻结强制标签对数似然差实验，只在校准集选择阈值和提示。
3. 入选中文短答案提示在校准集 TPR/TNR 均100%；在尚未使用的64条新模板验证上，TPR75%、TNR100%，未过门槛。比较关系类的8条正确候选全部被误拒。该验证集现已消耗，不再用于选择下一种方法。
4. 从缓存的CMRC2018 train建立192 train /64 dev /96 holdout，按文章隔离，并排除官方dev、历史检索评估和此前112题的文章/近重复。来自既有公开语料，不代表预训练未见，也不是新的外部来源。
5. 在64 dev上比较固定学生和教师，然后生成192条教师训练候选；96 holdout未执行模型推理。

## 缓存与故障边界

`scripts/resumable_teacher.py` 将输入、配置、源码和库版本绑定到缓存。逐条原子替换并核对预测hash；输入/配置/源码变化拒绝复用。实际进程在8条写入后以状态73退出；重启复用8条，只生成184条，已有hash未变。再次重放复用192条，新增0条，无需加载模型。

这是单机单生产者缓存，不支持并发写入。计算后、落盘前崩溃仍可能重复执行。file fsync与原子重命名不等于断电持久性或任务只执行一次；本次验证范围是进程中断恢复。

## 使用入口

以下从仓库根目录运行；`RUN_ROOT` 指外部证据目录，包含 `calibration-04`、`score-calibration-04`、`fresh-05`。公开证据现位于`reports/quality-study-20260920/`；原始分阶段命令需使用新的工作目录，不得写入冻结reports。

```bash

.venv-ci/bin/python scripts/verify_quality_screening.py "$RUN_ROOT"
# 导出独立于参考答案的待复核输入，以及分离的参考答案审计；目标必须不存在
.venv-ci/bin/python scripts/audit_teacher_cache.py \
  --data "$RUN_ROOT/fresh-05" --out work/teacher-audit-01
# 真实推理/恢复：需要 requirements.lock.txt 环境与协议指定的缓存模型
HF_HUB_OFFLINE=1 .venv/bin/python scripts/resumable_teacher.py \
  --data "$RUN_ROOT/fresh-05" --out "$RUN_ROOT/fresh-05/teacher-train" \
  --receipt work/replay-new-receipt.json
```

必须匹配执行源码与torch/transformers版本才能重用缓存；新实现/配置使用新目录。不要从单独复制的脚本路径运行推理：需要完整仓库的`qa_lab`模块。首次错误的快照路径重放产生`ModuleNotFoundError`，已保留失败日志；使用仓库入口后重放成功。

完整准备/推理参数见各脚本`--help`及保存的协议；离线重算和单元测试通过不代表模型质量提升。下一轮应预先冻结新核验验证集；不得通过在已失败验证集上改提示或阈值后报告独立通过。
