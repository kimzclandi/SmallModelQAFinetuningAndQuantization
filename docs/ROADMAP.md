# 项目状态与后续门槛

| 阶段 | 实现与运行状态 | 下一步条件 |
|---|---|---|
| 1 原始学生基线 | 数据/解码/评分/记录/必要测试已实现；真实执行证据见 reports | 保持固定数据和协议 |
| 普通SFT对照 | 24题/48步gold-SFT已训练和dev评估；有答案题回归，gate REJECT | 保留失败版本；不是教师蒸馏 |
| 2 教师蒸馏 | 已收到24条用户报告GPT回答并审计；尚未使用其训练 | 训练用途许可未确认；可换许可明确本地教师；API未授权 |
| 3 量化 | 方案候选 MLX 权重量化；尚未实现/运行 | 同框架浮点基线、硬件可运行性、误差和时延协议 |
| 4 数据改进 | 开发集失败队列与症状分类已实现；尚无再训练闭环 | 先诊断 dev，再冻结一次数据修订和实验 |
| GitHub 发布 | 只有本地独立仓库；无 remote、无上传、无线上 CI 结果 | 用户明确授权公开发布 |

教师仅返回文本时用响应/序列蒸馏；保留教师版本、时间、prompt、采样参数、原始响应、筛选理由和来源 ID。没有可对齐分布就不声称 logits 蒸馏。教师只读训练集输入，不访问 test；开发集仅作诊断。若使用金标准筛选教师样本，必须作为监督信息披露。

普通 SFT 与蒸馏组须匹配学生初始化、LoRA 配置、优化步数、训练 token 或清楚说明差异，单独衡量教师标签的增益。LoRA 是参数高效训练方式，不自动构成蒸馏。

量化需区分 weights 与 KV cache；当前 FP32 基线仅启用普通浮点 KV cache，无 KV 量化。MLX 转换后要重新跑同框架浮点模型；本阶段不默认 CUDA/bitsandbytes 可用。
