# 面试讲解与学习手册

状态：这是阶段一项目。以下知识尚未通过用户主动回忆验证，不能据此标记为“已掌握”。

## 领域地图

要解决的问题是：资源有限时，怎样把一个小模型变成更可靠、可测量的领域问答器。核心对象有输入证据、问题、目标响应、模型权重、评测协议、成本和失败样本。

主线：任务边界 → 数据隔离 → 原始学生 → 失败诊断 → 教师响应/普通标签的受控训练 → 同模型量化 → 回归评估。数据与评测贯穿每一步，不能到最后才补。

必须掌握：train/dev/test、EM/F1/拒答、生成参数、序列级蒸馏、LoRA、实验对照。进阶：校准、置信区间、教师偏差、量化误差与算子瓶颈。暂时可忽略：RLHF/RLAIF、特征蒸馏、复杂多智能体、生产服务界面。本轮实践重点是前四项，不先堆术语。

## 五个核心思维模型

| 思维模型 | 是什么/为何成立 | 适用与失效边界 | 面试和工程落地 |
|---|---|---|---|
| 测量先于优化 | 先定义目标和计分，再改模型；否则优化可能只迎合指标 | 用于所有对比；指标与真实需求不一致时失效 | 解释 EM 的别名/边界误差，同时人工审查 dev |
| 实验是反事实比较 | 只改变被研究因素，其他条件固定，才能归因 | 教师数据 vs gold-SFT；token 预算/数据量不同会混淆 | 等训练预算、同模型和推理配置，报告差异 |
| 拒答是有代价的决策 | 多答会增加无依据回答，多拒答会漏掉可答题 | 风险敏感 QA；标注不完整会误惩罚合理答案 | 拆开 answerable/unanswerable，不能只看总准确率 |
| 数据是依赖图 | 相同来源和近似问题不是独立样本；随机行切分高估泛化 | 同段多问题/改写；词相似度漏掉语义改写 | 在切分前合并家族，解释剩余污染风险 |
| 效率是系统属性 | 低比特减小权重，但真实速度取决于访存、算子和输出长度 | 量化/部署；不同框架硬件不能直接归因 | 区分存储/RSS/设备内存、TTFT/decode 吞吐 |

## 三个实践争议

1. **训练小模型还是先做好上下文/RAG？** 训练派希望把输出习惯和领域行为固化到权重；上下文派强调知识更新和证据可追踪。两者最有力的证据应是各自在相同任务、成本下的受控评测，不是模型排行榜。本项目给定文段，排除检索失败，能隔离回答行为；它没有验证 RAG 或闭卷知识。共识是先测瓶颈，哪种方案更好依赖知识变化速度、上下文质量和训练预算。
2. **教师生成标签是否必然优于人工 gold？** 支持方认为教师提供更一致的输出；反方指出错误和偏差会被继承。序列蒸馏研究说明它在某些任务中有效，但不证明任何教师数据均有益。隐含假设是教师在目标任务上足够可靠。实践需 baseline / gold-SFT / distilled 匹配对照，保留筛选记录；本项目当前没有证据支持教师收益。
3. **量化是否值得，低比特是否更快？** 支持方看重更小的权重和访存；谨慎方关注质量误差、反量化开销和内核支持。存储变小可由文件字节核验，加速必须在同框架实测。对于短回答，prefill 与调度可能主导。不存在脱离硬件、batch、上下文长度的“4-bit 一定快”结论；本项目尚未进行量化。

相关原始材料：[Sequence-Level Knowledge Distillation](https://arxiv.org/abs/1606.07947)、[LoRA](https://arxiv.org/abs/2106.09685)、[SQuAD 2.0](https://arxiv.org/abs/1806.03822)。这些研究的结论不直接转化为本项目的效果声明。

## 30 秒介绍

我在 Apple M4 Max 上构建了计算复杂性文段问答的小模型实验基线。按文段和近似问题家族隔离数据，运行固定版本 Qwen2.5-0.5B，保存逐条输出和可重算指标。102 道留出题 EM 是 24.51%，严格拒答失效，总分低于始终拒答对照。因此后续重点是诊断拒答行为，而不是宣称小模型已经优化成功。蒸馏、量化和数据修复闭环还没完成。

## 3 分钟讲解

先讲目标：不是做漂亮聊天页面，而是建立一个可复现、可归因的小模型优化实验室。为了降低变量，给定文段，不先加入检索。

再讲数据：从公开许可明确的 SQuAD 2.0 抽取计算复杂性文章，418 题，按家族分成 242/74/102。家族在切分前建立，原始来源 hash、处理配置、样本 ID 固定。它仍有同文章相关性和可能的预训练污染，所以不是新领域泛化证明。

再讲模型与测量：0.49B Instruct 模型、FP32、MPS、本地零 API 成本。greedy、batch=1、48 tokens 上限，原文答案或 NO_ANSWER。记录 EM/F1、拒答、格式、逐条 token 和同步时延；推理输入不含标签，完整覆盖校验防止只挑成功样本。自写计时解码器与标准 generate 做了训练样本一致性检查。

最后讲发现与下一步：有答案题测试 EM 52.08%，不可回答题严格正确拒答 0/54。开发集存在拒答格式变体与原文错误片段，症状不等于根因。下一步先在开发集诊断，再比较匹配预算的 gold-SFT 和响应蒸馏。量化另建同框架浮点对照；最终只做一轮数据改进并报告回归。初始两步LoRA smoke只证明入口可执行；随后24题gold-SFT pilot在dev总分提高，却使有答案EM回归，按预登记gate拒绝采用，不能称教师蒸馏成功。

## 公式与张量

单题 token F1 = 2c / (|P| + |G|)，P/G 是归一化后的预测/参考词序列，c 是多重集合交集个数。对多个参考答案取最大，再跨题平均。不可回答题单独按严格拒答计分。

LoRA：W' = W + (α/r)BA。W 为冻结的原权重 [d_out,d_in]；A 为 [r,d_in]、B 为 [d_out,r] 的可训练矩阵；r 是秩，α 控制缩放。它减少训练参数，但不自动减小基础权重占用，也不等同量化。

响应级训练：L = -Σ_t log pθ(y_t | x,y_<t) / T。x 是提示词与文段，y 是目标回答，T 是监督 token 数。训练入口 input_ids/labels 为 [1,L_seq]，prompt 的 labels=-100，只对回答及结束标记计算 causal LM loss。当前 y 来自 gold，并非教师。

## 深入追问与常见错误

- “你的独立测试集真的独立吗？”——仅相对于本项目训练/开发的家族隔离，不能排除预训练污染。
- “为什么总 EM 低于始终拒答？”——不可回答题比例大且严格拒答失败；需同时报告有答案能力，不能用保守策略总分替代能力。
- “LoRA 就是蒸馏吗？”——不是；LoRA 决定更新哪些参数，蒸馏决定监督来自教师的什么信息。
- “两步 loss 降了能写优化成功吗？”——不能，样本不同且没有独立质量比较；这只是执行验证。
- “为什么 token F1 有用又不够？”——测词重叠而非语义蕴含，可能奖励部分错误回答。
- “为什么不用 4-bit 就结束？”——压缩与速度是两个问题，还需质量和同条件时延对照。

错误回答包括：“无泄漏”“模型没见过测试题”“已完成蒸馏”“低比特必然加速”“格式对就答案对”。应改成有证据、有范围的陈述。

## 工程检查清单与最小实践

- 冻结数据、模型 revision、提示词、seed 和生成参数。
- 验证 ID 完整覆盖、gold 不进输入、指标能离线重算。
- 单独检查无答案题、格式变体、输出上限和失败分母。
- 测性能前预热与同步，区分内存口径；不要把自然输出变短当成系统加速。
- dev 诊断、test 留作预定评估，保存失败版本，不覆盖证据。

最小任务：复现两条 dev 预测，手算其中一条 F1；从 dev 找一条格式失败与一条原文错误片段，解释为何不能直接确定根因。训练 smoke 可运行，但不为了讲解额外访问 test。

## 新增复盘卡：为什么不能只看总分

普通gold-SFT在74条dev上EM从19/74升到41/74，但有答案题从19/33降到15/33。无答案正确拒答从0/41升到26/41，掩盖了答题回归。逐题修复26、退化4，gate REJECT。这个结果来自真实训练与固定dev，不是test提升，更不是教师数据增益。

用户提交的教师回答有17/24条与gold完全匹配，但7条分歧中混合了边界、题意/标注歧义和拒答问题。不要直接称7条幻觉，也不要事后改gold提高分数。训练集候选质量与独立泛化能力是两个问题。
